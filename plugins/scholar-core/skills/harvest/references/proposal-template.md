# Harvest proposal template

Copy to `scholar/harvest/pending/HRV-<YYYY-MM-DD>-<slug>.md`. Public-safe text only.

```
---
proposal_id: HRV-YYYY-MM-DD-slug
created: YYYY-MM-DD
source_project: generic
category: rule
problem: ""
observed_solution: ""
generalisability: ""
evidence_or_test: ""
proposed_target: ""
privacy_review: pending
review_status: proposed
owner_approval: pending
upstream_status: not-submitted
---

## Problem
What went wrong or was missing, in neutral words.

## What worked
The procedure or rule, step by step, with a made-up example if one helps.

## Evidence or test
Used in a real session and it worked, or untested idea. Name a test that would show it works.

## Suggested text
The exact rule, skill step or reference paragraph, ready to paste.

## Where it goes
Pack and skill or file. Say whether it changes an existing rule.
```

Field values
- `category`: rule, skill-fix, new-skill, research-gotcha, template.
- `privacy_review`: pending, passed.
- `review_status`: proposed, reviewed, accepted, declined.
- `owner_approval`: pending, approved, declined.
- `upstream_status`: not-submitted, branch-ready, bundle-exported, submitted, merged.

Visual-workflow lessons may be harvested as procedures, adapters, safe templates, fixtures and notes. Never harvest
private datasets, unlicensed figures, transcript excerpts or the scholar's interpretations.

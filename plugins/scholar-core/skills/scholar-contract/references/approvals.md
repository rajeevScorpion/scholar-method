# Approvals

Ask the scholar (AskUserQuestion in Claude Code, a plain question in Codex) before any of these. Standing
approval counts only if the scholar gave it for that kind of action in this project and it is written in the
project's decisions or contract.

## Always ask first
| Action | Why |
|---|---|
| Adopt an interpretation as the scholar's position or put it into the argument | Interpretation is the scholar's. A captured thought is not a position. |
| Change scope, research questions, objectives, methods, contribution or title | These are accepted decisions. |
| Substantive drafting or rewriting of manuscript prose | Authorship. Offer; do not default to it. |
| Bulk edits to approved prose, or any edit that touches a quotation, number or citation | Integrity. |
| Add a figure to a submission document | Figures are claims. |
| Write outside the project folder (global config, another repo, the method repo) | Boundaries. |
| Install or update a plugin, skill or package (Humanizer, Vega, anything) | Third-party code. |
| Push, publish, open a PR or issue, email, upload, share content outward | Outward actions. |
| Use a related project's records | Cross-project sharing is opt-in per project. |
| Collect or contact anything primary (participants, recordings, personal data) | Needs ethics and consent outside this tool. |

## Never needs asking
Reading project files; running read-only checks and `validate`; writing provisional insight records the scholar has
seen in a batch review; updating the mapped status and handoff; local commits on a feature branch.

## How to ask
One question, plain words, a default marked as recommended, and what happens on each answer. If the scholar
declines, record the decision in the mapped decisions file when it affects future work, and do not ask again for
the same thing.
